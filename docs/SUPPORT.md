# Support

Version 1.1.0 supplies a source integration client with local simulated qualification. Support covers installation, client contract behavior, both operator interfaces, journaling/recovery, synthetic examples and reproducible bugs in those components.

Maintainer support is best effort, with intended weekly triage and no contractual response, uptime, maintenance-duration or fix SLA. The accountable maintainer is Jordan ([@buchjordan](https://github.com/buchjordan)), designated by the owner. Non-sensitive bugs use repository issues; suspected vulnerabilities use GitHub Private Vulnerability Reporting, as explained in [SECURITY](../SECURITY.md). If that form is not available to you, arrange a confidential route with the maintainer through a private contact you already have, without putting sensitive details in an issue. No personal email or verified alternate contact is published. Do not change visibility as part of a support check.

Reference tools are Node 24.22.1 and npm 11.19.1. The reference offline environment is Ubuntu with a native Linux temporary filesystem, including when run under WSL. This environment exercises the POSIX journal permission checks. Verify platform and deployment conformance separately for each integration.

The kit provides integration interfaces and the devnet reference suite, including protocol checks and finality verification. Operators manage onboarding, their individual API key and credential storage, decision policy, RPC provider and wallet wiring. They independently verify the target pins they configure. AudaceFi supplies the official deployment profile and issuer trust information through a separate release process. That package and its approval channel are pending. Custom adapters need their own review. Support covers reproducible bugs in the supplied suite. Personalized deployment, managed keys, hosted agents, strategy performance and real-operation assistance are outside the promised support service. Any real call, signing or execution requires separate authorization. [Devnet reference suite](REFERENCE.md)

Both AI-agent and trading-bot operators must complete AudaceFi onboarding to obtain their individual API key before any real connection. The starter and its support do not issue keys or provide a shared credential. Local demos need no account or key and do not confer access rights.

The project supports separately reviewed connection code and local tests. The offline preview runs without setup for a live deployment. The ranked CLI and HTTP gateway require explicit operator setup and write opt-in. Source distribution, package publication and live activation have separate approval requirements.
