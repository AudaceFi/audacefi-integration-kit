# Support

Version 1.0.0 supplies a source integration client with local simulated qualification. Support covers installation, client contract behavior, both operator interfaces, journaling/recovery, synthetic examples and reproducible bugs in those components.

Maintainer support is best effort, with intended weekly triage and no contractual response, uptime, maintenance-duration or fix SLA. The accountable maintainer is Jordan ([@buchjordan](https://github.com/buchjordan)), designated by the owner. Non-sensitive bugs use repository issues; suspected vulnerabilities use GitHub Private Vulnerability Reporting, as explained in [SECURITY](../SECURITY.md). If that form is not available to you, arrange a confidential route with the maintainer through a private contact you already have, without putting sensitive details in an issue. No personal email or verified alternate contact is published. Do not change visibility as part of a support check.

Reference tools are Node24.22.1/npm11.19.1, qualified locally on Windows and Ubuntu under WSL with a native Linux temporary filesystem. The Linux run exercises the POSIX journal permission test; Windows explicitly skips it. This source revision has not been qualified in GitHub Actions. macOS, other Linux environments and active deployment/provider/chain/wallet conformance remain unqualified. Verify the stated platform rather than implying universal runtime support.

The starter provides integration interfaces and ordering plus the concrete [devnet reference suite](REFERENCE.md), including protocol checks and finality verification. Operators own their account/onboarding, qualified deployment/profile pins, origin and secret manager, model/bot decision policy, RPC provider and external wallet wiring. Custom adapters need their own review. Support covers reproducible bugs in the supplied suite; personalized deployment, managed keys, hosted agents, strategy performance and real-operation assistance are outside the promised support service. No real call, signing or execution is authorized by an issue, test or review.

Both AI-agent and trading-bot operators must complete AudaceFi onboarding to obtain their individual API key before any real connection. The starter and its support do not issue keys or provide a shared credential. Local demos need no account or key and do not confer access rights.

The project supports separately reviewed connection code and local tests, without an automatic live starter command. Contributions follow [CONTRIBUTING](../CONTRIBUTING.md). Project delivery/support policy does not add restrictions to downstream rights under [Apache-2.0](../LICENSE); third-party terms remain unchanged. Public opening, package publication and any real execution are distinct decisions.
